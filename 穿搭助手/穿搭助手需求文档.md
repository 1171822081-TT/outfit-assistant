# 穿搭助手（每日穿搭推荐）— 需求文档

---

## 一、项目概述

### 1.1 项目背景
女朋友衣服鞋子太多，每天晚上纠结第二天穿什么。需要一个工具根据天气自动推荐搭配，并在 3D 模特上展示效果。

### 1.2 核心目标
- 自动获取第二天天气，免去手动查天气的麻烦
- 建立可视化的电子衣柜，管理所有衣物
- 根据天气智能推荐 3 套搭配
- 支持在 3D 模特上自由搭配试穿

### 1.3 用户角色
- **主要用户**：女朋友（日常使用）
- **次要用户**：你（帮忙录入衣物、维护系统）

## 二、功能需求

### 2.1 天气模块

| 编号 | 功能 | 描述 |
|------|------|------|
| F1.1 | 自动定位 | 首次使用时获取用户所在城市，后续可手动切换 |
| F1.2 | 明日天气展示 | 首页顶部展示：天气图标、温度范围、风力、降水概率、穿衣指数 |
| F1.3 | 天气数据来源 | 对接免费天气 API（推荐：和风天气 / OpenWeatherMap） |
| F1.4 | 定时提醒 | 每晚 20:00 可通过浏览器通知或微信推送提醒查看明日穿搭 |

### 2.2 衣柜模块

| 编号 | 功能 | 描述 |
|------|------|------|
| F2.1 | 衣物录入 | 上传衣物照片、填写属性（种类、颜色、风格、厚薄、适合温度范围） |
| F2.2 | 分类陈列 | 按种类分组展示：上衣 / 下装 / 连衣裙 / 鞋子 / 外套 / 配饰 |
| F2.3 | 筛选过滤 | 按颜色、款式、季节、厚薄等条件筛选 |
| F2.4 | 衣物管理 | 增删改查，标记"已收纳/常用/闲置"状态 |
| F2.5 | 拍照录入 | 支持手机拍照直接录入衣柜（PWA 或小程序版本） |

**衣物属性设计：**

```
种类：短袖T恤 / 长袖衬衫 / 卫衣 / 毛衣 / 短裤 / 长裤 / 短裙 / 长裙 / 
      连衣裙 / 薄外套 / 厚外套 / 羽绒服 / 运动鞋 / 皮鞋 / 短靴 / 长靴 / 凉鞋

颜色：黑 / 白 / 灰 / 红 / 蓝 / 绿 / 黄 / 粉 / 棕 / 卡其 / 牛仔蓝 / 碎花

风格：休闲 / 通勤 / 运动 / 甜美 / 酷飒 / 温柔

厚薄：轻薄 / 适中 / 加厚 / 羽绒

适合温度：最低温 ~ 最高温（如 15°C ~ 25°C）
```

### 2.3 智能推荐模块

| 编号 | 功能 | 描述 |
|------|------|------|
| F3.1 | 天气匹配 | 根据明日温度、风力、降水，匹配衣柜中适合的衣物 |
| F3.2 | 三套推荐 | 生成 3 套搭配，分别标注风格（如"通勤优雅""休闲舒适""甜美可爱"） |
| F3.3 | 推荐逻辑 | 优先考虑温度匹配 → 降水（是否下雨影响鞋子和外套选择）→ 风格统一 → 颜色协调 |
| F3.4 | 3D 展示 | 每套推荐搭配穿在 3D 模特上，支持旋转、缩放查看 |
| F3.5 | 一键上身 | 点击某套搭配，自动将所有衣物穿戴到模特身上 |
| F3.6 | 收藏/跳过 | 喜欢的搭配可收藏，不喜欢的可换一批 |

**推荐规则示例：**

| 天气条件 | 推荐策略 |
|----------|----------|
| 温度 > 28°C，晴天 | 优先短袖/短裤/短裙/凉鞋，推荐轻薄透气 |
| 温度 20-28°C，晴天 | T恤+长裤/长裙，可加薄外套备用 |
| 温度 10-20°C | 薄外套/卫衣+长裤，运动鞋/皮鞋 |
| 温度 0-10°C | 毛衣+厚外套+长裤+短靴/长靴 |
| 温度 < 0°C | 羽绒服+毛衣+加厚裤+长靴/雪地靴 |
| 下雨/下雪 | 优先防水外套、不推荐浅色裤子、推荐防滑鞋 |

### 2.4 自定义搭配模块

| 编号 | 功能 | 描述 |
|------|------|------|
| F4.1 | 衣柜拖拽 | 从衣柜中拖拽衣物到模特身上的对应部位 |
| F4.2 | 分类替换 | 点击模特某部位（如上衣），弹出衣柜中该类别所有衣物供选择 |
| F4.3 | 实时预览 | 切换衣物后模特实时更新外观 |
| F4.4 | 保存搭配 | 自定义搭配可保存到"我的搭配"中，下次直接使用 |
| F4.5 | 搭配日历 | 记录每天穿了什么，回看历史穿搭 |

### 3.3 3D 模特方案（重点难点）

这是一个需要重点说明的技术挑战。**真正的 3D 衣物建模+穿戴在技术上非常复杂**，以下是分层方案：

#### 方案 A：2D 纸娃娃系统（推荐 MVP 阶段使用）

- 使用一个 2D 模特底图（正面全身照/插画）
- 衣物以 PNG 图层形式按顺序叠加（内衣 → 上衣 → 下装 → 外套 → 鞋子）
- 切换衣物 = 切换对应图层的图片
- **优点**：开发简单，几天可完成；衣物只需拍照抠图
- **缺点**：不支持 360° 旋转，层次感有限

#### 方案 B：3D 模特 + 贴图换装（推荐目标方案）

- 使用 Three.js 加载一个基础 3D 人体模型（可用 MakeHuman / Ready Player Me / Mixamo 的免费模型）
- 衣物不是真正的 3D 服装，而是**在 3D 身体上替换不同的贴图纹理**
- 上衣、裤子、鞋子等各部位使用独立的材质/纹理
- 切换衣物 = 切换对应部位的纹理贴图
- **优点**：支持 360° 旋转缩放，有一定立体感，开发难度适中
- **缺点**：衣物没有真实的厚度和褶皱，看起来像紧身衣

#### 方案 C：真正的 3D 服装建模（远期方案）

- 使用 Marvelous Designer / Clo3D 等专业软件制作衣物 3D 模型
- 在引擎中做布料物理模拟
- **优点**：效果最真实
- **缺点**：每条衣服都需要专业建模，工作量巨大，技术门槛极高

**建议路线：先用方案 A（2D 纸娃娃）快速上线让女朋友用起来，同时开发方案 B 作为升级版本。**

### 3.4 搭配推荐引擎设计

```
推荐流程：
1. 获取明日天气数据（温度、天气状况、风力）
2. 计算"天气特征向量"：[最高温, 最低温, 降水概率, 风力等级, 天气类型]
3. 从衣柜中筛选出满足温度条件的候选衣物
4. 按风格对候选衣物分组
5. 在每组内，按颜色搭配规则生成组合
6. 选出得分最高的 3 套，确保风格差异化
7. 返回推荐结果
```

**颜色搭配规则（简化版）：**
- 全身不超过 3 个主色
- 基础色（黑白灰牛仔蓝）可任意搭配
- 亮色单品配基础色下装
- 同色系深浅搭配加分

## 五、数据设计

### 5.1 数据库表结构

```sql
-- 衣物表
CREATE TABLE clothing (
  id          INTEGER PRIMARY KEY,
  name        TEXT NOT NULL,          -- 名称（如"白色短袖T恤"）
  category    TEXT NOT NULL,          -- 种类：top/bottom/dress/outerwear/shoes/accessory
  subcategory TEXT,                   -- 子类：tshirt/shirt/hoodie/shorts/pants/skirt/...
  color       TEXT,                   -- 颜色
  color_hex   TEXT,                   -- 颜色值 #FFFFFF
  style       TEXT,                   -- 风格：casual/office/sport/sweet/cool/gentle
  thickness   TEXT,                   -- 厚薄：thin/medium/thick/down
  temp_min    INTEGER,                -- 适合最低温度
  temp_max    INTEGER,                -- 适合最高温度
  image_url   TEXT,                   -- 衣物照片路径
  status      TEXT DEFAULT 'active',  -- active/stored/idle
  created_at  DATETIME DEFAULT NOW()
);

-- 搭配表（一套搭配）
CREATE TABLE outfit (
  id          INTEGER PRIMARY KEY,
  name        TEXT,                   -- 搭配名称
  top_id      INTEGER,               -- 上衣ID
  bottom_id   INTEGER,               -- 下装ID
  dress_id    INTEGER,               -- 连衣裙ID（与上衣/下装互斥）
  outerwear_id INTEGER,              -- 外套ID
  shoes_id    INTEGER,               -- 鞋子ID
  accessory_id INTEGER,              -- 配饰ID
  is_recommended BOOLEAN,            -- 是否系统推荐
  weather_condition TEXT,            -- 推荐时的天气条件
  is_favorite BOOLEAN DEFAULT FALSE, -- 是否收藏
  created_at  DATETIME DEFAULT NOW()
);

-- 穿搭日记表
CREATE TABLE diary (
  id          INTEGER PRIMARY KEY,
  date        DATE NOT NULL,
  outfit_id   INTEGER,
  weather_info TEXT,                  -- 当天天气JSON
  rating      INTEGER,               -- 满意度评分 1-5
  note        TEXT,
  created_at  DATETIME DEFAULT NOW()
);
```

### 6.2 MVP 阶段技术降级方案

考虑到你是零基础，MVP 阶段可以做以下简化，**用最低成本先跑起来**：

| 原需求 | MVP 简化方案 |
|--------|-------------|
| 3D 模特展示 | → 2D 模特图片 + CSS 图层叠加（衣物照片抠图后叠上去） |
| 自动天气 | → 对接和风天气 API（免费，一天 1000 次调用足够） |
| 智能推荐 3 套 | → 按温度区间硬编码规则，从衣柜筛选 |
| 自定义穿着 | → 下拉选择 / 点击切换，无需拖拽 |
| 完整后端 | → 用 **Supabase / Firebase** 做 BaaS，无需自己写后端 |
