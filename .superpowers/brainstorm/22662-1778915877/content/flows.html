第 4 节：关键流程

推荐引擎 + 图片自动处理，两条核心链路

流程一：搭配推荐引擎

输入：明日天气 + 衣柜所有衣物
输出：3 套搭配，风格互不相同

① 获取天气数据
   调用和风天气 API → 拿到 [最高温, 最低温, 天气类型, 风力, 降水概率]

② 筛选候选衣物
   从衣柜过滤：衣物的 temp_min ≤ 明日最高温 AND 衣物的 temp_max ≥ 明日最低温
   下雨 → 鞋类排除凉鞋/布面鞋，外套排除无防水材质
   如果候选为空 → 放宽温度 ±3°C 再筛一次

③ 按风格分组生成搭配
   在每个风格组内，尝试组合成完整搭配（上衣+下装+鞋+外套）：
   - 颜色冲突检测：主色超过 3 个 → 降分
   - 风格一致性：同套搭配内各单品的 style 标签一致 → 加分
   - 厚薄一致：上衣和外套的厚度相差不超过一档 → 加分
   - 连衣裙路径：有连衣裙时跳过上衣+下装配对

④ 选出 Top 3，风格差异化
   按得分排序，取前 3，确保 style 不重复。
   若只剩 2 种风格 → 第 3 套用"随机搭配"补齐
   若只有 1 种风格 → 放宽风格约束，从其他风格混搭生成

⑤ 返回结果
   每套附带：搭配名称、衣物清单、风格标签、匹配得分

流程二：电商图片自动处理

输入：淘宝/电商商品图
输出：去背景透明 PNG，可叠加到模特身上

① 用户录入衣物
   粘贴图片 URL 或上传文件 → 保存到 Supabase Storage → clothing.image_original
   同时创建 image_queue 记录 (status: pending)

② 浏览器端 AI 抠图
   使用 @imgly/background-removal，在 Web Worker 中运行（不卡主线程）
   处理中 → image_queue status = "processing"，前端显示进度条

③ 处理完成
   成功 → 透明 PNG 上传 Supabase Storage → clothing.image_naked
   失败 → image_queue status = "failed"，提示用户"图片背景太复杂，请换一张纯色背景的图"

④ 手动兜底
   图片处理失败的衣物在衣柜中标记"待处理"状态
   用户可手动上传已处理好的透明 PNG 替换

降级策略：推荐引擎

异常 降级方案
天气 API 失败 展示缓存的上次天气 + "天气数据可能不是最新"提示
温度匹配无结果 放宽温度 ±3°C 再筛；仍无结果则提示"该温度区间暂无合适衣物"
衣柜衣物太少 (<5件) 能做几套做几套，不足 3 套的显示"先录入更多衣物吧"引导
风格不足 3 种 放宽风格约束，允许同风格不同单品组合出多套
