第 5 节：错误处理与边界情况

所有可能出问题的地方，都有兜底

网络异常

场景 处理
天气 API 超时/失败 显示 localStorage 缓存的上次天气 + 黄色标签"天气不是最新的"
Supabase 连接失败 衣柜从 localStorage 读缓存，顶部红条提示"网络异常，数据可能不是最新"
图片上传失败 保留表单已填内容，图片区域显示"上传失败，点击重试"
全部 API 不可用 展示上次完整缓存的快照 + 提示"当前为离线模式"

空状态

页面 空状态
首页 — 无推荐 引导卡片："衣柜里还没有适合明天天气的衣物，去添加几件吧 →"
衣柜 — 空 插图 + "衣柜还是空的" + 大按钮"添加第一件衣物"
我的搭配 — 无收藏 "还没有收藏搭配，去首页看看推荐 →"
搭配日历 — 无记录 "今天还没记录穿搭，要记录吗？"

加载状态

场景 方案
首页首次加载 天气卡片 + 模特区域 骨架屏闪烁，完成后渐显
推荐生成中 模特区域显示"正在为你搭配..." + 脉冲动画
图片抠图中 进度条 + "正在处理图片..." 百分比
衣柜列表加载 6 个灰色卡片骨架屏占位

边界情况

边界 处理
衣柜只有 1-2 件 能做几套做几套，不硬凑 3 套，引导加衣物
全部衣物同一种风格 风格差异化的约束自动放宽，允许同风格不同单品
极端天气（高温/寒潮） 无匹配时放宽温度 ±5°C，再没有则提示"建议添置适合XX天气的衣物"
用户未完成问卷就退出 下次打开继续弹窗，提供"跳过"按钮，默认使用中性参数
图片抠图失败 标记"待处理"，衣柜中覆盖半透明遮罩，点击可重新处理或手动上传 PNG
同一天反复打开 天气和推荐结果用当天日期做 key 缓存，不重复调用 API
