从路线 A 迁移到路线 B 的难度

React SPA → Next.js + PWA，到底要改多少？

一句话结论：低到中等难度，不伤筋动骨

Next.js 本身就是基于 React 的，你的组件代码 90% 不用改。迁移更像是"换个壳"而非"重写"。

迁移要动的东西

模块 路线 A 路线 B 改动量
UI 组件 React 组件 完全复用 零改动
Supabase 调用 @supabase/supabase-js 完全复用 零改动
天气 API fetch 调用 完全复用 零改动
路由 react-router Next.js 文件路由 中
入口文件 Vite / CRA 配置 next.config.js 中
PWA 能力 无 新增 manifest + Service Worker 新增
迁移路径：3 步走，不影响使用
第 1 步：创建 Next.js 项目，搬组件
把路线 A 的 React 组件原样搬进 Next.js 的 app/ 目录，路由改成文件夹结构。Supabase 调用和天气 API 代码不变。

第 2 步：加 PWA 能力
安装 next-pwa 插件，配置 manifest.json（图标、名称、主题色），设置缓存策略（天气数据缓存 1 小时，衣柜数据实时）。

第 3 步：替换部署
Vercel 上新建项目关联新仓库，DNS 切过来。旧版本留着当回退。

估算

AI 辅助下，整个迁移大约 2-4 天。主要是路由重组的体力活，没有技术难点。

建议：放心选 A，先跑起来。 路线 A 到 B 的过渡很平滑——代码复用率 90%，迁移成本低。先用 A 让女朋友用上，体验反馈有了再决定要不要做 PWA。
